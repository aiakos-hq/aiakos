# Risk register

This is the index of known risks and unverified assumptions. Each risk lives in its source spec
or spike, under a stable ID, with its full reasoning; this file only lists them so they can be
found and checked in one place. IDs are `<spec>-RK<n>` for spec risks (for example `0005-RK3` is
`RK3` in spec 0005) and `S<spike>-<n>` for open items from spikes. `<spec>-FU<n>` marks a
follow-up found while building this register that the spec's owner still has to apply. An ID is
never reused.

## When to review it

- **At each milestone boundary**: walk every `open` row of the milestone that is ending and of
  the one that starts.
- **Before each implementation PR**: check the rows whose owner issue is the issue being
  implemented, and say in the PR which ones it checks or closes.

## How to close a risk

1. Check it as the "How it's checked" column says (test, measurement or experiment).
2. Record the outcome in the source doc: under the risk itself for a spec (and under "Changes
   after acceptance" if the spec changes), or in the spike's findings.
3. Set the status here: `resolved` (checked, the risk did not happen or is handled),
   `accepted` (checked, the risk stays and the maintainer accepts it) or `superseded` (the design
   changed so it no longer applies). Name the PR or doc that did it.

New risks are added in the source doc first and then indexed here in the same PR.
